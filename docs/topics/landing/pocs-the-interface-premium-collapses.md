## en
- **Number: spend build time on curation, not the explorer UI.** Since a product-grade data explorer is now an agent weekend, not a moat, decide upfront that Number's defensibility is the licensed-reading curation and correctness guarantee, not frontend polish, and put Fable's time on the data/ontology side.
- **gitboard: don't treat dashboard polish as a differentiator.** A nice service dashboard is cheap to build now; keep gitboard's value in the guarantee it gives (accurate CI/health state), and skip investing further in UI beyond clarity.
- **Auditor: apply the "what couldn't be conjured" test to reports.** For any audit or methodology write-up, check what the next person with the same prompt could not reproduce; that remainder, not the report's presentation, is what to defend as the Auditor's actual output.

## ko
- **Number: 익스플로러 UI가 아니라 큐레이션에 시간을 쓴다.** 제품급 데이터 익스플로러가 이제 에이전트가 주말에 만드는 수준이 된 이상, Number의 방어력은 라이선스된 읽기의 큐레이션과 정확성 보증에 있다고 미리 정하고 Fable의 시간을 데이터·온톨로지 쪽에 쓴다.
- **gitboard: 대시보드 완성도를 차별점으로 삼지 않는다.** 괜찮은 서비스 대시보드는 이제 저렴하게 만들 수 있다. gitboard의 가치는 그것이 주는 보증(정확한 CI/헬스 상태)에 두고, 명료함을 넘어서는 UI 투자는 하지 않는다.
- **Auditor: "재현할 수 없는 것" 테스트를 보고서에 적용한다.** 어떤 감사나 방법론 문서든, 같은 프롬프트를 가진 다음 사람이 재현할 수 없는 부분을 점검한다. 보고서의 표현이 아니라 그 나머지가 Auditor가 실제로 지켜야 할 산출물이다.
