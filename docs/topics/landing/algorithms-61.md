## en
- **Devnet: since a single-node Anvil fork can't demonstrate data availability sampling, treat "what happens to Verex settlement if DA fails" as a design doc item to write before Devnet moves toward a real L2/OP-Stack.**
- **Verex: define an explicit halt/fallback state for market settlement when the data-availability check fails, instead of assuming posted data is always available.**
- **Auditor: if Jayverse adopts an L2 later, require the light-client sampling parameters (sample count vs. target confidence) to be documented and checked, not just "we use an L2."**

## ko
- **Devnet: 단일 노드 Anvil 포크로는 데이터 가용성 샘플링을 보여줄 수 없으므로, Devnet이 실제 L2/OP-Stack으로 옮겨가기 전에 "DA가 실패하면 Verex 정산이 어떤 상태로 남는가"를 설계 문서 항목으로 미리 적는다.**
- **Verex: 데이터 가용성 체크가 실패했을 때 마켓 정산을 위한 명시적 정지/폴백 상태를 정의하고, 게시된 데이터가 항상 가용하다고 가정하지 않는다.**
- **Auditor: 나중에 Jayverse가 L2를 도입한다면 라이트 클라이언트 샘플링 파라미터(샘플 수 대비 목표 신뢰도)를 문서화하고 체크하도록 요구한다. "L2를 쓴다"는 진술만으로는 부족하다.**
