## en
- **gitboard: switch the dashboard's metric to shipped units, not planned ones.** The roadmap's real lesson is 27 projects over 100+ resources; apply the same ratio to Jayverse and track merged, deployed increments per service per month instead of open PRs or backlog size.
- **Game: budget Unity work in the same tiered way.** The Unity street where Verex markets appear on boards has its own "atoms" cost — asset and scene production time — so set a monthly tier (a fixed hours budget) and require one playable increment shipped per tier, not open-ended asset polishing.
- **CI: green pipelines are not the deliverable.** A passing pipeline is this catalogue's "resource read," not its "project shipped" — track deployed Cloud Run revisions per week as the real metric alongside CI status.

## ko
- **gitboard: 대시보드 지표를 계획된 것이 아니라 배포된 것으로 바꾼다.** 로드맵의 진짜 교훈은 리소스 100개+ 대비 프로젝트 27개다. 같은 비율을 Jayverse에 적용해, 열린 PR이나 백로그 크기 대신 서비스별 월간 머지·배포 증분을 추적한다.
- **Game: Unity 작업도 같은 단계별 예산으로 짠다.** Verex 마켓이 보드에 표시되는 Unity 거리에도 자체적인 "물성" 비용이 있다. 에셋과 씬 제작 시간이다. 월별 티어(고정 시간 예산)를 정하고, 무한정 에셋을 다듬는 대신 티어마다 플레이 가능한 증분 하나를 배포하도록 요구한다.
- **CI: 파이프라인 통과는 결과물이 아니다.** 통과한 파이프라인은 이 카탈로그가 말하는 "읽은 리소스"이지 "배포한 프로젝트"가 아니다. CI 상태와 별개로 주간 Cloud Run 배포 리비전 수를 진짜 지표로 추적한다.
