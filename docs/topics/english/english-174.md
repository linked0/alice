# 174 · Line — No feature ships that requires a licence we don't have a path to.
title_ko: No feature ships that requires a licence we don't have a path to. — 취득 경로가 없는 라이선스를 요구하는 기능은 출시하지 않는다
situation: Roadmap planning. Priya, the product manager, wants a fiat on-ramp for EU users next quarter. Jay, as tech lead, has to say why it may not make the roadmap without sounding like he is against the feature: the team's rule is about licences, not about ambition.
situation_ko: 로드맵 회의. 프로덕트 매니저 Priya가 다음 분기에 EU 사용자용 법정화폐 온램프를 넣고 싶어 한다. 테크 리드인 Jay는 그 기능에 반대하는 것처럼 들리지 않으면서 왜 로드맵에 못 들어갈 수도 있는지 말해야 한다. 팀의 규칙은 야심이 아니라 라이선스에 관한 것이다.
why: **No feature ships that requires a licence we don't have a path to** sounds like a rule rather than a case-by-case call because the subject is "No feature" and the verb is "ships", as in "No code ships without review". **Have a path to X** means a credible plan to obtain X, not possession, so the rule separates three states: licence in hand, no licence yet but a path, and no path at all. Only the last one blocks. The stranded "to" belongs to the relative clause "a licence [we have a path to]". "Ship" means release to real users.

"No code ships without review"와 같은 틀이다. **Have a path to X**는 X를 보유했다는 게 아니라 X를 얻을 현실적인 계획이 있다는 뜻이라, 규칙은 세 상태를 가른다. 라이선스 보유, 아직 없지만 경로가 있음, 경로조차 없음. 마지막 것만 막는다. 문장 끝의 "to"는 관계절 "a licence [we have a path to]"의 것이다. "Ship"은 실제 사용자에게 출시한다는 뜻이다.

## Dialogue
Priya: I want the EU fiat on-ramp on next quarter's roadmap. Users keep asking for it.
> 다음 분기 로드맵에 EU 법정화폐 온램프를 넣고 싶어요. 사용자들이 계속 요청해요.
Jay: Then we need a path to the e-money licence first. No feature ships that requires a licence we don't have a path to.
> 그럼 먼저 전자화폐 라이선스를 얻을 경로가 필요해요. 취득 경로가 없는 라이선스를 요구하는 기능은 출시하지 않으니까요.
Priya: We don't have the licence yet. Does that block it?
> 아직 라이선스가 없잖아요. 그게 막는 건가요?
Jay: Not having it isn't the blocker; having no path is. If legal can show a credible route, say an EMI partner by Q3, it goes on the roadmap with that as a dependency.
> 없는 게 막는 게 아니라 경로가 없는 게 막는 거예요. 법무팀이 현실적인 경로, 예를 들어 3분기까지 EMI 파트너를 제시하면, 그걸 의존성으로 달고 로드맵에 올라가요.
Priya: And if legal comes back with nothing?
> 법무팀이 아무것도 못 가져오면요?
Jay: Then it doesn't ship, and we say so in the doc up front instead of building it and hoping.
> 그럼 출시하지 않고, 만들어 놓고 기대하는 대신 문서에 처음부터 그렇게 적어요.

## Techniques
1. **원칙을 "No X ships that…" 꼴로 말하면 개인 의견이 아니라 팀 규칙으로 들린다.** "No feature ships that requires a licence we don't have a path to." — 반대가 아니라 조건을 말하는 것이 된다.
2. **막는 조건을 좁혀서 말한다.** "Not having it isn't the blocker; having no path is." — 라이선스 부재와 경로 부재를 구분해 주면 상대는 무엇을 가져오면 되는지 안다.

## Expressions
| Expression | 뜻 · 쓰이는 자리 |
|---|---|
| No feature ships that … | …한 기능은 출시하지 않는다 — 출시 원칙을 규칙처럼 말할 때. "No feature ships that requires a licence we don't have a path to." |
| have a path to X | X를 얻을 현실적인 경로가 있다 — 라이선스, 흑자 전환 등. "a credible route" |
| ship a feature | 기능을 실제 사용자에게 출시하다 — 개발 영어의 기본 동사 |
| with that as a dependency | 그것을 의존성으로 달고 — 로드맵에 조건부로 올릴 때 |
